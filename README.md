# PA Lab-Violation Detection System (Faster R-CNN & DeepSORT)

Proyek ini adalah sistem deteksi pelanggaran di laboratorium komputer (seperti bermain game di HP, tidur, dan makan) menggunakan model **Faster R-CNN**, pelacakan objek **DeepSORT**, backend **Flask** dengan **Socket.IO** untuk komunikasi real-time, serta frontend **Next.js** dan interface alternatif berbasis HTML/Flask.

Data deteksi serta foto pelanggaran akan disimpan secara otomatis ke **Supabase Database** dan **Supabase Storage**.

---

## ⚙️ Persiapan dan Instalasi (Setup)

### 1. Database & Storage (Supabase)

Sebelum menjalankan aplikasi, Anda perlu menyiapkan akun dan project di [Supabase](https://supabase.com/):

1. **Buat Tabel `detections`**:
   Jalankan query SQL berikut di SQL Editor Supabase Anda untuk membuat tabel log deteksi:
   ```sql
   create table detections (
     id bigint generated by default as identity primary key,
     frame_time text not null,
     frame_number int not null,
     object_name text not null,
     confidence float not null,
     tracking_id int,
     timestamp timestamptz default now(),
     image_path text
   );
   ```
2. **Buat Storage Bucket**:
   * Buat bucket baru bernama `violations`.
   * Pastikan untuk mencentang opsi **Public** agar URL gambar deteksi bisa diakses langsung oleh frontend.

---

### 2. Konfigurasi Backend (Python)

1. **Buat dan Aktifkan Virtual Environment (Sangat Disarankan)**:
   Langkah ini memastikan bahwa semua library/dependensi tersimpan khusus di dalam folder proyek ini (`.venv`), tidak bercampur dengan Python global di komputer Anda.

   ```bash
   # 1. Buat folder virtual environment
   python -m venv .venv

   # 2. Aktifkan virtual environment
   source .venv/bin/activate  # Untuk macOS/Linux
   # atau
   .\.venv\Scripts\activate   # Untuk Windows (PowerShell/CMD)
   ```

   *(Pastikan muncul tulisan `(.venv)` di terminal Anda yang menandakan environment sudah aktif).*
2. **Install Dependensi**:
   Setelah virtual environment aktif, baru jalankan perintah ini agar library terinstal di dalam `.venv`:

   ```bash
   pip install -r requirements.txt
   ```
3. **Siapkan File Model**:

   * Siapkan file bobot model Faster R-CNN di `models/best_model-gabungan6.pth`.
   * Path tersebut adalah nilai default `MODEL_PATH` di `backend/main.py`. Jika memakai checkpoint lain, ubah `MODEL_PATH` sesuai lokasinya.
   * Checkpoint lama dapat disimpan di `models/legacy/`.
4. **Konfigurasi Environment Variable (`.env`)**:

   * Buat file bernama `.env` di root folder proyek ini.
   * Pilih provider database dengan variabel `DB_PROVIDER` (lihat section **Pilihan Database** di bawah).

## 🗄️ Pilihan Database

Aplikasi ini mendukung dua provider database yang dapat dipilih melalui variabel `DB_PROVIDER` di file `.env`.

| Fitur              | Supabase                 | PostgreSQL (Self-hosted)        |
| ------------------ | ------------------------ | ------------------------------- |
| Setup              | Daftar di supabase.com   | Install PostgreSQL lokal/server |
| Penyimpanan Gambar | Supabase Storage (cloud) | Folder lokal`violations/`     |
| Auto-migrate tabel | ❌ (buat manual)         | ✅ (otomatis)                   |
| Cocok untuk        | Produksi / cloud         | Lokal / jaringan internal       |

### Opsi A: Menggunakan Supabase (Default)

Isi file `.env` dengan:

```env
# Provider database
DB_PROVIDER=supabase

# Konfigurasi Supabase
SUPABASE_URL=https://project-id-anda.supabase.co
SUPABASE_KEY=api-key-anon-atau-service-role-supabase-anda
```

> Pastikan bucket **`violations`** (Public) dan tabel **`detections`** sudah dibuat di Supabase (lihat section Setup Supabase di atas).

### Opsi B: Menggunakan PostgreSQL Self-Hosted

1. **Install PostgreSQL** di komputer/server Anda jika belum ada.
2. **Buat database baru** (misalnya bernama `lab_violations`):

   ```sql
   CREATE DATABASE lab_violations;
   ```
3. **Isi file `.env`** dengan:

   ```env
   # Provider database
   DB_PROVIDER=postgresql

   # Connection string PostgreSQL
   # Format: postgresql://user:password@host:port/dbname
   DATABASE_URL=postgresql://postgres:password@localhost:5432/lab_violations
   ```
4. **Jalankan aplikasi**. Tabel `detections` akan **dibuat secara otomatis** saat pertama kali dijalankan.
5. Gambar pelanggaran akan disimpan di folder **`violations/`** di root proyek dan dapat diakses melalui `http://localhost:5000/violations/<filename>`.
6. **Masuk ke Folder Frontend**:

   ```bash
   cd frontend
   ```
7. **Install Dependensi Node.js**:
   Aplikasi ini dikonfigurasi menggunakan lockfile `pnpm`. Disarankan menginstalnya dengan `pnpm` (jika belum punya, jalankan `npm install -g pnpm` terlebih dahulu):

   ```bash
   pnpm install
   # atau jika ingin menggunakan npm biasa:
   npm install
   ```
8. **Konfigurasi Environment Variable (`.env.local`)**:

   * Buat file `.env.local` di dalam folder `frontend/`.
   * Isi dengan informasi Supabase:
     ```env
     NEXT_PUBLIC_SUPABASE_URL=https://project-id-anda.supabase.co
     NEXT_PUBLIC_SUPABASE_ANON_KEY=api-key-anon-supabase-anda
     ```

## 🚀 Cara Menjalankan Aplikasi

### Langkah 1: Jalankan Backend Flask

Di terminal utama (pastikan virtual environment aktif jika menggunakannya):

```bash
python backend/main.py
```

Backend akan berjalan di: **`http://localhost:5000`**

### Langkah 2: Jalankan Frontend Next.js

Buka terminal baru, masuk ke folder `frontend`, lalu jalankan:

```bash
cd frontend
pnpm dev
# atau: npm run dev
```

Frontend akan berjalan di: **`http://localhost:3000`**

Buka browser Anda dan akses **`http://localhost:3000`** untuk masuk ke antarmuka dashboard deteksi pelanggaran real-time!

*(Catatan: Anda juga bisa mengakses tampilan web sederhana bawaan Flask langsung di `http://localhost:5000` jika frontend Next.js tidak dijalankan).*

## 🎮 Panduan Penggunaan (How to Use)

Setelah aplikasi backend dan frontend berhasil dijalankan, Anda dapat menggunakannya dengan fitur-fitur berikut:

### 1. Deteksi Pelanggaran dari File Video (Halaman Home)

Halaman utama digunakan untuk memproses file rekaman video CCTV lab yang sudah ada:

1. Akses halaman utama di browser: **`http://localhost:3000`**.
2. Pada panel **Upload Video**, klik area dropzone atau seret file video (format: `MP4`, `AVI`, `MOV` dengan batas maksimal `100MB`) yang ingin dianalisis.
3. Klik tombol **Upload & Deteksi**.
4. Deteksi berjalan secara real-time:
   * **Live Preview**: Menampilkan frame video yang sedang diproses lengkap dengan bounding box hijau di sekitar objek yang terdeteksi beserta ID pelacakannya (misal: `sleep ID:1`).
   * **Detection Logs**: Menampilkan tabel log deteksi real-time. Anda dapat melihat waktu kejadian, nomor frame, nama objek/pelanggaran, dan tingkat keyakinan (confidence score).
   * **Bukti Foto**: Klik gambar mini (thumbnail) di kolom *Gambar* pada tabel log untuk memperbesar bukti pelanggaran.
5. **Hentikan Deteksi**: Jika ingin membatalkan proses deteksi di tengah jalan, Anda dapat mengeklik tombol **Stop** (tombol merah dengan ikon lingkaran) di sebelah tombol upload.
6. **Ekspor Log**: Anda bisa mengeklik tombol **Export Excel** untuk mengunduh log deteksi dari sesi tersebut ke dalam file Excel `.xlsx`.

### 2. Deteksi Pelanggaran dari Live Stream (Halaman Stream URL)

Digunakan untuk menghubungkan aplikasi secara langsung ke kamera CCTV atau RTSP stream:

1. Pastikan server dan kamera berada di **jaringan yang sama** (WiFi Kampus / LAN Lab).
2. Jalankan backend (`python backend/main.py`). Server berjalan di `http://0.0.0.0:5000`.
3. Akses halaman stream dari browser:
   - **Dari server sendiri**: `http://localhost:5000/url`
   - **Dari perangkat lain di WiFi Kampus**: `http://<IP-SERVER>:5000/url`
     > Cari IP server dengan perintah `ipconfig` (Windows) atau `ip a` (Linux).
     >
4. Masukkan URL stream ke kolom input:
   - **Format RTSP umum**: `rtsp://user:password@ip-kamera:554/stream`
   - **ZoneMinder CCTV PENS** (jika sudah login ke jaringan kampus):

     ```
     rtsp://<user>:<pass>@<ip-zoneminder>:554/zm/video.mp4?monitor=<id>
     ```

     Atau gunakan URL RTSP yang disediakan ZoneMinder di halaman `cctv.pens.ac.id`.
5. Klik **Mulai Deteksi**. Sistem akan:
   - Membuka koneksi RTSP dengan retry otomatis (hingga 10x percobaan, interval 5 detik)
   - Menampilkan **Live Preview** via MJPEG stream yang efisien
   - Menampilkan panel **Performance Monitor** real-time (FPS, Inference Time, CPU, RAM, GPU)
   - Menyimpan log pelanggaran ke database dan menampilkan di tabel Detection Logs
   - Mencatat metrik performa ke file CSV di folder `logs/` setiap detik
6. Klik **Stop Stream** untuk menghentikan deteksi.
7. Klik **Export Perf CSV** untuk mengunduh file CSV log performa (untuk analisis beban server).
8. Klik **Export Excel** untuk mengunduh log deteksi pelanggaran ke format `.xlsx`.

#### 🎬 Simulasi RTSP Lokal (untuk Testing tanpa Kamera Fisik)

Jika belum ada kamera RTSP, bisa menggunakan FFmpeg untuk mensimulasikan RTSP server dari file video lokal:

1. **Install FFmpeg** (jika belum ada): https://ffmpeg.org/download.html
2. **Install RTSP Simple Server** (sebagai RTSP relay):
   ```bash
   # Download dari: https://github.com/bluenviron/mediamtx/releases
   # Jalankan:
   ./mediamtx
   ```
3. **Push video ke RTSP server**:
   ```bash
   ffmpeg -re -stream_loop -1 -i "uploads/1594528-video.mp4" -c:v libx264 -preset ultrafast -pix_fmt yuv420p -an -f rtsp -rtsp_transport tcp rtsp://localhost:8554/lab
   ```
4. **Masukkan URL** `rtsp://localhost:8554/lab` ke halaman Stream URL.

#### 📊 Analisis Log Performa (untuk Riset)

File CSV performa tersimpan di folder `logs/` dengan format:

```
logs/stream_perf_YYYYMMDD_HHMMSS.csv
```

Kolom CSV:

| Kolom                | Keterangan                            |
| -------------------- | ------------------------------------- |
| `timestamp`        | Waktu pencatatan (ISO 8601)           |
| `source_url`       | URL sumber stream                     |
| `fps_actual`       | FPS aktual yang diproses model        |
| `inference_ms`     | Waktu inferensi Faster R-CNN (ms)     |
| `preprocess_ms`    | Waktu preprocessing frame (ms)        |
| `cpu_percent`      | Persentase penggunaan CPU             |
| `ram_mb`           | Penggunaan RAM (MB)                   |
| `gpu_percent`      | Penggunaan GPU (0 jika tidak ada GPU) |
| `gpu_mem_mb`       | Penggunaan VRAM GPU (MB)              |
| `frames_processed` | Jumlah frame yang telah diproses      |
| `detections_count` | Jumlah pelanggaran yang terdeteksi    |
| `uptime_seconds`   | Durasi stream aktif (detik)           |

Download via endpoint: `GET /api/stream_metrics/export`

Lihat daftar semua log: `GET /api/stream_metrics/logs`

### 3. Halaman Statistik & Ringkasan (Dashboard)

Untuk melihat statistik visual tentang tingkat pelanggaran di laboratorium:

1. Klik menu **Dashboard** pada navigasi atas.
2. Anda akan disajikan metrik total pelanggaran yang terdeteksi dan visualisasi diagram persentase berdasarkan jenis pelanggaran (`sleep`, `eating`, `playing game phone`).

### 4. Halaman Riwayat Pelanggaran (History)

Digunakan untuk melihat, memfilter, dan memeriksa log pelanggaran yang telah lalu yang tersimpan di database:

1. Klik menu **History** pada navigasi atas.
2. Gunakan filter pencarian berdasarkan **Jenis Pelanggaran** atau **Tanggal** untuk mempermudah pencarian.
3. Anda dapat melihat gambar bukti pelanggaran yang disimpan secara permanen.
