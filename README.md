# PA Lab-Violation Detection System

Sistem deteksi pelanggaran di laboratorium komputer dari video rekaman atau live
stream CCTV. Deteksi memakai Faster R-CNN, pelacakan objek memakai DeepSORT,
backend Flask dengan Socket.IO, frontend Next.js, dan halaman HTML sederhana
yang dilayani Flask untuk pemakaian cepat.

Jenis pelanggaran yang dideteksi: bermain game di ponsel, tidur, dan makan.

Hasil deteksi disimpan ke database. Pilihan database ada dua:

- Supabase, foto bukti diunggah ke Supabase Storage.
- PostgreSQL lokal, foto bukti disimpan ke folder `violations/`.

---

## Fitur

- Deteksi dari file video yang diunggah (maksimal 100 MB, format MP4, AVI, MOV, MKV, WMV, FLV).
- Deteksi dari live stream RTSP atau HTTP dengan reconnect otomatis sampai 10 percobaan, jeda 5 detik.
- Pelacakan objek DeepSORT dengan cooldown 5 detik per ID, supaya satu kejadian tidak tercatat berulang.
- Live preview. Halaman upload menerima frame lewat Socket.IO, halaman stream memakai MJPEG di `/video_feed`.
- Monitoring performa: FPS, waktu inferensi, waktu preprocessing, CPU, RAM, dan GPU (GPU aktif bila `pynvml` terpasang).
- Log performa ditulis ke CSV setiap 1 detik di `logs/`.
- Riwayat deteksi dengan filter jenis pelanggaran dan tanggal, plus ekspor Excel yang dibuat di sisi frontend dengan library `xlsx`.
- Dashboard statistik pada `/dashboard`.

dijalankan. Isinya tidak di-commit karena bersifat sementara atau berukuran besar.

## Prasyarat

- Python 3.10 atau lebih baru (proyek ini dikembangkan di Python 3.12).
- Node.js dan pnpm untuk frontend.
- Database, pilih salah satu: Supabase atau PostgreSQL lokal.
- Opsional: FFmpeg dan mediamtx untuk simulasi RTSP lokal.

## Instalasi

### 1. Backend Python

Jalankan semua perintah dari root proyek.

```bash
python -m venv .venv

# Windows
.\.venv\Scripts\activate
# macOS/Linux
source .venv/bin/activate

pip install -r requirements.txt
```

`requirements.txt` memuat `psutil` untuk monitoring CPU dan RAM. Monitoring GPU
memakai `pynvml` dan bersifat opsional: `pip install pynvml`.

### 2. Bobot Model

Letakkan file bobot Faster R-CNN di `models/best_model-gabungan6.pth`. Path ini
adalah nilai `MODEL_PATH` di `backend/main.py`. Jika memakai checkpoint lain,
ubah `MODEL_PATH` sesuai lokasinya.

Urutan kelas model harus sama dengan urutan saat training:
`["background", "playing game phone", "sleep", "eating"]`.

### 3. Konfigurasi `.env`

Buat file `.env` di root proyek. Nilai `DB_PROVIDER` menentukan database yang
dipakai, dan defaultnya adalah `supabase`.

Untuk Supabase:

```env
DB_PROVIDER=supabase
SUPABASE_URL=https://project-id-anda.supabase.co
SUPABASE_KEY=api-key-supabase-anda
```

Untuk PostgreSQL:

```env
DB_PROVIDER=postgresql
DATABASE_URL=postgresql://postgres:password@localhost:5432/lab_violations
```

### 4. Setup Database

#### Opsi A: Supabase

Buat tabel `detections` lewat SQL Editor:

```sql
create table detections (
  id bigint generated by default as identity primary key,
  frame_time text not null,
  frame_number int not null,
  object_name text not null,
  confidence float not null,
  tracking_id int,
  timestamp timestamptz default now(),
  image_path text
);
```

Buat Storage bucket bernama `violations` dan tandai sebagai Public, supaya URL
gambar bisa diakses frontend.

#### Opsi B: PostgreSQL

Buat database, misalnya:

```sql
CREATE DATABASE lab_violations;
```

Tabel `detections` dibuat otomatis oleh backend saat pertama kali dijalankan.
Gambar bukti disimpan di folder `violations/` dan diakses lewat
`http://localhost:5000/violations/<filename>`.

### 5. Frontend

```bash
cd frontend
pnpm install
```

Frontend tidak memerlukan file env saat ini. Alamat backend di-hardcode ke
`http://localhost:5000` pada halaman upload, dashboard, dan stream, sementara
`next.config.ts` mem-proxy request `/api/*` dan `/violations/*` ke backend yang
sama. Halaman riwayat memakai jalur proxy tersebut.

## Menjalankan Aplikasi

Terminal 1, jalankan backend dari root proyek:

```bash
python backend/main.py
```

Backend berjalan di `http://localhost:5000` (bind `0.0.0.0:5000`).

Terminal 2, jalankan frontend:

```bash
cd frontend
pnpm dev
# atau: npm run dev
```

Frontend berjalan di `http://localhost:3000`. Buka `http://localhost:3000` untuk
antarmuka utama, atau `http://localhost:5000` untuk halaman HTML bawaan Flask.

Catatan akses dari perangkat lain di jaringan yang sama: halaman stream memakai
`http://<hostname>:5000` untuk memanggil backend. Pastikan port 5000 dan 3000
terbuka di firewall server.

## Panduan Penggunaan

### 1. Deteksi dari File Video (`/`)

1. Buka `http://localhost:3000`.
2. Seret file video ke dropzone, atau klik untuk memilih file (format MP4, AVI, MOV, MKV, WMV, FLV, maksimal 100 MB).
3. Klik Upload & Deteksi.
4. Deteksi berjalan dan menampilkan live preview berisi bounding box hijau dengan ID pelacakan, plus tabel log deteksi.
5. Klik Stop untuk menghentikan deteksi di tengah proses.
6. Klik Export Excel untuk mengunduh log sesi tersebut sebagai file `.xlsx`.
7. Klik thumbnail gambar di tabel log untuk memperbesar bukti pelanggaran.

Backend memproses satu frame setiap 5 detik video untuk menekan beban, dan hanya
menyimpan deteksi dengan skor di atas 0.6.

### 2. Deteksi dari Live Stream (`/url`)

1. Pastikan server dan kamera berada di jaringan yang sama.
2. Masukkan URL stream, misalnya `rtsp://user:password@ip-kamera:554/stream`, lalu klik Mulai Deteksi.
3. Sistem membuka koneksi dengan reconnect otomatis sampai 10 percobaan, menampilkan live preview MJPEG, dan menampilkan panel performa (FPS, inference time, CPU, RAM, GPU).
4. Klik Stop Stream untuk menghentikan deteksi.
5. Klik Export Perf CSV untuk mengunduh log performa, atau Export Excel untuk log pelanggaran.

Contoh URL ZoneMinder di jaringan kampus:

```
rtsp://<user>:<pass>@<ip-zoneminder>:554/zm/video.mp4?monitor=<id>
```

### 3. Dashboard Statistik (`/dashboard`)

Halaman ini menampilkan total pelanggaran dan persentase per jenis pelanggaran.
Halaman ini belum ditautkan di navbar, jadi buka langsung lewat
`http://localhost:3000/dashboard`.

### 4. Riwayat Pelanggaran (`/history`)

Halaman ini menampilkan riwayat deteksi dari database dengan pagination, filter
jenis pelanggaran, dan filter tanggal. Klik gambar bukti untuk memperbesar, atau
klik Export Excel untuk mengunduh halaman riwayat yang sedang tampil.

## API Backend

| Method | Endpoint                          | Fungsi                                              |
| ------ | --------------------------------- | --------------------------------------------------- |
| GET    | `/`                               | Halaman upload HTML (Flask)                         |
| GET    | `/url`                            | Halaman stream HTML (Flask)                         |
| GET    | `/history`                        | Halaman riwayat HTML (Flask)                        |
| POST   | `/upload_video`                   | Unggah video dan mulai deteksi                      |
| POST   | `/stop_detection`                 | Hentikan deteksi video yang sedang berjalan         |
| GET    | `/video_feed`                     | Live preview MJPEG                                  |
| POST   | `/detect_from_stream`             | Mulai deteksi dari URL RTSP/HTTP                    |
| POST   | `/stop_stream`                    | Hentikan stream yang sedang berjalan                |
| GET    | `/stream_status`                  | Status dan metrik stream aktif                      |
| GET    | `/api/stream_metrics/logs`        | Daftar file log performa CSV                        |
| GET    | `/api/stream_metrics/export`      | Unduh CSV performa (parameter `filename`, opsional) |
| GET    | `/api/detections`                 | Riwayat deteksi (`page`, `per_page` default 15, `object_name`, `date`) |
| GET    | `/api/detections/stats`           | Statistik untuk dashboard                           |
| GET    | `/violations/<filename>`          | File gambar bukti pelanggaran                       |

`/api/detections` dan `/api/detections/stats` mengembalikan status 503 bila
adapter database tidak tersedia.

## Event Socket.IO

| Event             | Arah            | Isi                                                       |
| ----------------- | --------------- | --------------------------------------------------------- |
| `violation_alert` | server ke klien | Deteksi pelanggaran baru (objek, confidence, ID, gambar)  |
| `object_lost`     | server ke klien | Objek yang dilacak hilang dari frame                      |

| `stream_error`    | server ke klien | Stream gagal dibuka setelah batas reconnect tercapai      |

## Simulasi RTSP Lokal

Kalau belum ada kamera RTSP, FFmpeg dan mediamtx bisa dipakai untuk membuat
stream uji dari file video lokal.

1. Install FFmpeg dari https://ffmpeg.org/download.html.
2. Unduh mediamtx dari https://github.com/bluenviron/mediamtx/releases, lalu jalankan `./mediamtx`.
3. Push video ke server RTSP:

   ```bash
   ffmpeg -re -stream_loop -1 -i "uploads/1594528-video.mp4" -c:v libx264 -preset ultrafast -pix_fmt yuv420p -an -f rtsp -rtsp_transport tcp rtsp://localhost:8554/lab
   ```

4. Masukkan URL `rtsp://localhost:8554/lab` pada halaman Stream URL.

## Log Performa

File CSV tersimpan di `logs/` dengan nama `stream_perf_YYYYMMDD_HHMMSS.csv`.
Kolom yang ditulis:

| Kolom              | Keterangan                            |
| ------------------ | ------------------------------------- |
| `timestamp`        | Waktu pencatatan (ISO 8601)           |
| `source_url`       | URL sumber stream                     |
| `status`           | Status stream (idle, connecting, active, reconnecting, stopped) |
| `fps_actual`       | FPS aktual yang diproses model        |
| `inference_ms`     | Waktu inferensi Faster R-CNN (ms)     |
| `preprocess_ms`    | Waktu preprocessing frame (ms)        |
| `cpu_percent`      | Persentase penggunaan CPU             |
| `ram_mb`           | Penggunaan RAM (MB)                   |
| `gpu_percent`      | Persentase penggunaan GPU (0 jika tidak ada GPU) |
| `gpu_mem_mb`       | Penggunaan VRAM GPU (MB)              |
| `frames_processed` | Jumlah frame yang sudah diproses      |
| `detections_count` | Jumlah pelanggaran yang terdeteksi    |
| `uptime_seconds`   | Durasi stream aktif (detik)           |

Daftar file: `GET /api/stream_metrics/logs`. Unduh file: `GET /api/stream_metrics/export`.

## Catatan Teknis

- Kelas model dan urutan label harus sama dengan notebook training, jika tidak, hasil deteksi akan salah.
- Ambang confidence deteksi adalah 0.6.
- Video upload diproses satu frame setiap 5 detik video.
- Satu ID pelacakan hanya dicatat sekali per 5 detik untuk pelanggaran yang sama.
- Model dimuat sekali saat backend start. Jika file model tidak ditemukan, backend tetap jalan dan mencetak peringatan "Model path not found".

## Troubleshooting

| Gejala                                   | Penyebab dan solusi                                                        |
| ---------------------------------------- | -------------------------------------------------------------------------- |
| `WARNING: Model path not found`          | File bobot belum ada di `models/best_model-gabungan6.pth`.                  |
| `[DB] WARNING: SUPABASE_URL ... belum diset` | Isi `SUPABASE_URL` dan `SUPABASE_KEY` di `.env`.                        |
| API riwayat mengembalikan 503            | Adapter database gagal dibuat. Periksa nilai `DB_PROVIDER` dan kredensial.  |
| GPU selalu 0                             | `pynvml` belum terpasang atau GPU bukan NVIDIA.                            |
| Frontend gagal memanggil API             | Pastikan backend berjalan di port 5000.                                    |
